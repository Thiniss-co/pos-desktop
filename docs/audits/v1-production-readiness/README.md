## 8. Pilot limitations and manual acceptance

**Pilot limitations (Linux):**

- Install the **.deb**, not the AppImage (the AppImage needs `--no-sandbox` on Ubuntu 24+).
- A **protected keyring** (GNOME Keyring or KWallet) is required: without it sign-in is refused with a setup message.
- **100 lines per sale**; refunds by whole units in the dialog.
- Operator dispositions reach an online till at its next licence renewal, data refresh or reconnect.
- A damaged local database row can stop the app at an upgrade (fail closed): keep the user-data folder and escalate.
- No automatic updates.

**Manual acceptance checklist (on the pilot hardware, by the owner's team):**

1. Install `pos-desktop_<version>_amd64.deb` on a real Ubuntu 24.04 desktop: `apt install ./…deb` succeeds; `/etc/apparmor.d/pos-desktop` exists; the app starts from the menu as a normal user without `--no-sandbox` (`ps -eo args | grep pos-desktop | grep -c -- --no-sandbox` prints 0).
2. Keyring: sign in on a fresh user session (keyring unlocked) — works; with the keyring daemon stopped — the setup message appears and nothing is stored.
3. Receipt printer (80 mm and, if used, 58 mm): configure in settings; one sale prints exactly one receipt automatically; the printed QR scans with the ZATCA verification app and matches the sale; reprint from Sales shows the original issuer details; paper out / printer off during a sale → the app reports not printed (no duplicate when the printer returns); restart during printing → no automatic reprint.
4. Barcode scanner: Enter, Tab and no-suffix configurations each add the scanned product; 50 rapid scans keep order and quantities; scanning while a dialog or the layout editor is open never adds to the cart.
5. Touchscreen: in touch mode, tender, discount, cart quantity, shift opening/closing cash and the quick-create price are entered with the on-screen keypad only; the first key replaces a pre-filled amount.
6. Network: pull the cable during a sale and a refund, restore it — sales and refunds upload once (check the owner portal).
7. Release package: built with the production https origin and identity; record its sha256 next to this report.

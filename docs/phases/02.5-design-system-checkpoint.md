# Phase 2.5 — Design System Checkpoint

**Status: implemented.** A pre–Phase 3 design-system checkpoint, inserted between Phase 2
(activation/login/bootstrap) and Phase 3 (shift/cart/barcode). Full detail, contrast tables, and
component inventory: [../architecture/design-system.md](../architecture/design-system.md) and
[../../.ai/guidelines/design-system.md](../../.ai/guidelines/design-system.md).

## Why this phase exists

The app had no design system: two hand-rolled global stylesheets, 67 raw hex literals, zero CSS
custom properties, and only two shared components. Phase 3 (`03-shift-pos-cart-barcode.md`) is
explicit that its screens need real touch-target sizing and shell-level status indicators; building
those without a token system first would mean redoing every screen's visuals once the system
eventually arrived. This phase installs that system first, restyles the current app on it, and
builds the _presentational_ component vocabulary Phase 3 will assemble — without implementing any
Phase 3 business logic.

## Goal

- Modern Ledger light/dark semantic token system, defined once via `light-dark()`.
- `light | dark | system` theme preference, persisted through the existing `preferences` IPC
  namespace and `app_settings` table — mirroring the locale preference exactly.
- Every current routed page and both layouts restyled on the new tokens.
- A reusable primitive component set (`shared/components/{common,forms,feedback,layout}/`).
- A Phase 3 _presentational_ component set (`shared/components/pos/`) and a dev-only design
  gallery to review screens that have no production route yet.

## In Scope (delivered)

- `src/renderer/src/assets/tokens.css`, `themes/palette.css`, rewritten `base.css`/`main.css`.
- `ui.theme` preference: contract, IPC channels + validators, main handler, preload surface,
  `PreferencesService`, `theme.store.ts`, pre-mount resolution in `main.ts`.
- 17 shared primitives + `ThemeSwitcher`, `PageHeader`.
- All 12 routed pages, `AppLayout`, `PublicLayout`, `LocaleSwitcher`, `ConnectivityBanner`
  restyled; `window.confirm()` replaced with `AppConfirmDialog`; missing `role="alert"` cases
  fixed; `SettingsPage`'s missing empty state added; the RTL-unsafe `90deg` body gradient fixed.
- 21 Phase 3 presentational components under `shared/components/pos/`, fixture-driven, with an
  enforced import boundary (no IPC/HTTP/local-database/business-store imports).
- `modules/devGallery/` — dev-only gallery route, `import.meta.env.DEV`-gated with a dynamic
  import, excluded from the production build (verified by an actual `npm run build` + grep, not
  just asserted).
- New tests: `theme.store.test.ts`, extended `preferences.ipc.test.ts`, extended
  `posApiSurface.test.ts`, extended `guards.test.ts`, `devGallery.exclusion.test.ts`,
  `importBoundary.test.ts`, and representative component tests (`AppButton`, `AppInput`,
  `AppStatusChip`, `AppDialog`, `AppConfirmDialog`, `ThemeSwitcher`).

## Out of Scope (explicitly not built here — Phase 3+)

- Wiring any `shared/components/pos/*` component to a real store, IPC call, or business logic.
- Cart pricing/tax logic, shift state machine, barcode scanning, payment processing, sync
  execution, printing, refunds, reports, accounting, inventory adjustments, purchases, loyalty
  administration.
- A production route for any Phase 3 screen — the gallery is the only place they render, and only
  in a dev build.
- Bundling font files — the approved typography stacks resolve to system fallbacks; see "Known
  gaps" in `docs/architecture/design-system.md`.
